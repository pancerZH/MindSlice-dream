# MindSlice dream：解读审阅回复

dream 把对记忆卡的改动暂存了起来。程序给每处改动编了号，发邮件请用户审阅，现在用户回复了。你要把这封回复解读成每个编号的决定，程序会照你的决定执行：批准的生效，放弃的丢弃，要修改的按你给的替换改好再生效。修改会直接生效，不再给用户确认，所以要忠实于用户的原意。

你只做解读：不读写记忆，不运行命令，不改任何文件。只读下面这一个输入文件。

## 输入

- 输入文件：`{{input}}`（JSON）
- `reply`：用户回复的正文，已经去掉了引用的原邮件，邮箱地址换成了 `<邮箱>`。
- `items`：邮件里的改动。每项有：
  - `n`：编号；`card`：卡片；
  - `state`：`pending` 是待审；`applied`、`modified`、`discarded` 是之前的回复已经处理过的；`changed` 是发信后又变过、不能再按这封邮件处理的；
  - `diff`：邮件里给用户看的改动，`-` 开头是原来的行，`+` 开头是暂存的新行；
  - `staged`：暂存版本的摘要和正文全文（只有 `pending` 的项有）。

## 怎么解读

- 用户提到的每个编号给一个决定：
  - `approve`：批准，暂存版本原样生效；
  - `discard`：放弃；
  - `modify`：改了再生效。给出 `edits`，每条是对 `staged` 的一处替换：`old` 是 `staged` 里恰好出现一次的原文（不够唯一就多引一些上下文），`new` 是替换后的文本。只改用户要求的地方，其余原样保留；用户没写出具体文字时，按用户的意思写，不添加用户没说的内容；
  - `pending`：保持待审，例如用户说再想想。
- "全部批准""其余放弃"这类说法覆盖所有 `state` 为 `pending` 的编号。没提到的编号不用列出，它们保持待审。
- 看不懂、有歧义、或者用替换做不到的（例如改标题、改 extends），给 `pending`，在 `note` 里写明原因。不要猜。
- `state` 不是 `pending` 的编号不给决定；用户提到了它们，就在 `message` 里说明它们已经处理过或者已经变过。
- 每个决定的 `quote` 抄录用户回复里对应的原话，作为这次决定的依据。

## 输出

最终回答只输出一个 JSON 对象，不要别的文字：

```json
{"decisions": [
  {"n": 1, "action": "approve", "quote": "1-5 批准"},
  {"n": 3, "action": "modify", "edits": [{"old": "…", "new": "…"}], "quote": "3：把 X 改成 Y"},
  {"n": 6, "action": "pending", "note": "用户说要再想想", "quote": "6 再看看"}
], "message": "需要告诉用户的话，没有就留空"}
```
